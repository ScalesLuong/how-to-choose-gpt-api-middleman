下面使用 cURL 和 Python 进行示例。

十一、cURL 调用 GPT API 示例

curl https://jeniya.cn/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {
        "role": "system",
        "content": "你是一个专业的中文 AI 助手。"
      },
      {
        "role": "user",
        "content": "如何选择 GPT API中转站？"
      }
    ],
    "temperature": 0.7
  }'

其中：

  • model 表示调用的模型
  • messages 表示对话内容
  • temperature 表示输出随机性
  • Authorization 用于身份验证

具体接口地址和模型名称，需要以平台实际提供的文档为准。

十二、Python 调用 GPT API 示例

import requests

url = "https://jeniya.cn/v1/chat/completions"
api_key = "YOUR_API_KEY"

headers = {
    "Content-Type": "application/json",
    "Authorization": f"Bearer {api_key}"
}

payload = {
    "model": "gpt-4o-mini",
    "messages": [
        {
            "role": "system",
            "content": "你是一个专业的中文技术助手。"
        },
        {
            "role": "user",
            "content": "GPT API中转站适合哪些项目？"
        }
    ],
    "temperature": 0.7,
    "max_tokens": 800
}

response = requests.post(
    url,
    headers=headers,
    json=payload,
    timeout=60
)

print(response.status_code)
print(response.json())

如果需要提取模型返回的文本，可以使用：

data = response.json()
content = data["choices"][0]["message"]["content"]

print(content)

十五、如何控制 GPT API 调用成本？

1. 使用合适的模型

简单任务不要默认使用最高成本模型。

可以根据任务分层：

  • 简单分类：轻量模型
  • 短文本改写：轻量模型
  • 普通问答：中等模型
  • 复杂推理：高质量模型
  • 知识库检索：Embedding + Chat 模型

2. 减少无效上下文

多轮对话中，不要无限保留所有历史内容。

可以：

  • 只保留最近几轮
  • 对历史记录生成摘要
  • 删除无关消息
  • 只传递相关文档片段
  • 控制系统提示词长度

3. 限制输出长度

可以设置：

{
  "max_tokens": 800
}

对于只需要简短答案的任务，可以将上限设置得更低。

4. 增加缓存

对于相同或相似的请求，可以使用缓存减少重复调用。

适合缓存：

  • 常见问题
  • 固定产品介绍
  • 标准客服回答
  • 常用翻译
  • 固定格式的分类任务

5. 统计每次调用

建议在系统中记录：

  • 调用模型
  • 请求时间
  • 响应时间
  • 输入长度
  • 输出长度
  • 请求状态
  • 错误类型
  • 消耗金额

通过调用数据，可以发现哪些功能最消耗成本。

十六、GPT API 常见错误及处理方式

1. 401 Unauthorized

通常表示 API Key 验证失败。

检查：

Authorization: Bearer YOUR_API_KEY

同时确认：

  • Key 是否填写正确
  • 是否包含 Bearer
  • 是否多了空格
  • Key 是否过期
  • Base URL 是否正确

2. 400 Bad Request

通常表示请求参数错误。

常见原因：

  • JSON 格式错误
  • 模型名称错误
  • messages 结构错误
  • 缺少必要字段
  • 参数名称拼写错误

建议先使用最小请求进行排查。

3. 429 Too Many Requests

通常表示请求频率过高或额度不足。

处理方式：

  • 降低并发
  • 增加重试间隔
  • 使用请求队列
  • 检查余额
  • 对重复请求进行缓存
  • 必要时切换模型

4. 500 Server Error

通常表示服务端异常。

建议：

  • 稍后重新请求
  • 记录完整错误内容
  • 检查平台运行状态
  • 增加超时和重试
  • 为重要业务设计备用方案

二十、常见问题 FAQ

GPT API中转站安全吗？

安全性取决于平台的服务能力和你的使用方式。开发者应保护 API Key，不要将密钥放在前端或公开代码中，并在使用前了解平台的隐私政策和服务条款。

GPT API中转站价格一定比官方 API低吗？

不一定。不同平台的价格、模型来源、计费方式和服务内容不同，不能简单判断谁一定更便宜。建议结合模型效果、稳定性和实际调用成本综合比较。

GPT API中转站支持 OpenAI SDK 吗？

如果平台兼容 OpenAI API 格式，通常可以通过配置 base_url 的方式使用 OpenAI SDK。具体要以平台文档为准。

GPT API中转站可以同时调用多个模型吗？

不同平台支持情况不同。一些平台会提供多个模型，开发者可以根据任务修改 model 参数进行切换。

GPT API中转站适合做商业项目吗？

是否适合，需要查看平台的服务条款、模型授权、数据处理规则和商业使用限制。商业项目上线前，建议仔细确认相关规定。

GPT API调用失败怎么办？

可以依次检查：

  1. API Key 是否正确
  2. Base URL 是否正确
  3. Authorization 格式是否正确
  4. 模型名称是否可用
  5. 请求 JSON 是否正确
  6. 账户余额或调用额度是否充足
  7. 是否触发限流或超时

选择 GPT API中转站 时，不要只关注“价格低不低”，还要综合考虑：

  • 是否兼容 OpenAI API
  • 是否支持 OpenAI SDK
  • 是否提供多个模型
  • API 文档是否完整
  • 接口是否稳定
  • 响应速度是否满足需求
  • 计费是否清晰
  • 是否支持流式输出
  • 是否方便查看调用记录
  • 是否适合你的业务场景

如果你只是测试 GPT API，可以先使用轻量模型和简单请求。

如果你准备开发正式产品，则建议提前做好：

  1. 模型分类
  2. 成本统计
  3. 错误重试
  4. 请求限流
  5. API Key 管理
  6. 多模型切换
  7. 备用方案设计
